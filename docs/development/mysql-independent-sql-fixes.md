# MySQL SQL generation regressions

The MySQL dialect and its MariaDB and Aurora MySQL subclasses now generate:

- `DELETE FROM table` for clearing a temporary table, preserving the existing
  use of DELETE so the operation can participate in a transaction.
- `BINARY(16)` for the portable `DataType.UUID`, matching its existing binary
  JDBC handler. The model type remains UUID.
- `TINYBLOB` when recreating native TINYBLOB columns, preserving their 255-byte
  capacity instead of widening them to BLOB.
- A column self-assignment for `ON DUPLICATE KEY UPDATE` when there are no
  mutable columns. Generated columns are excluded and `updateableColumn`
  configuration is respected. Ordinary MERGE assignments remain unchanged.

The no-op assignment still uses MySQL's duplicate-key UPDATE operation; UPDATE
triggers and the driver's affected-row conventions still apply. This change
does not change which unique-key conflicts trigger that operation.

Public Java APIs, configuration formats, dependencies and resolver boundaries
are unchanged. UUID DDL changes from an unsupported native type to its existing
binary representation. Existing database objects are not modified automatically.
The production changes are confined to `sqlapp-core-mysql`; the MariaDB and
Aurora MySQL modules add regression tests for inherited behavior.

## Validation

The regression tests were added before the implementation changes. They failed
for all four defects on MySQL, MariaDB and Aurora MySQL before the fixes.

MySQL SQL-generation tests cover the base 5.x dialect, 5.6.4, 5.6.5, 5.7, 8.0,
8.0.1, 8.4 and 9.0. MERGE cases include single and composite keys, generated
columns alongside keys, quoted identifiers and explicitly excluded updates.
MariaDB tests cover representative 10.x, 11.x and 12.x versions; Aurora tests
cover its 8.0 and 8.4 compatibility dialects.

Run the relevant module suites with Java 25 and the repository wrapper:

```powershell
.\gradlew.bat :sqlapp-core-mysql:test :sqlapp-core-mariadb:test :sqlapp-core-aurora-mysql:test --offline --console=plain
```

On 2026-11-17 these suites passed: MySQL 335 tests, MariaDB 103 tests and Aurora
MySQL 23 tests, with no failures, errors or skipped tests.

Generated SQL was also executed against disposable, network-isolated local
containers using MySQL 5.7.44, 8.0.46 and 8.4.11, and MariaDB 11.4.12. Checks
confirmed BINARY(16)/TINYBLOB catalog types, stored binary lengths, inserting and
repeating key-only/composite-key MERGE, generated-column values, preserving an
excluded payload on duplicate MERGE, and clearing/rolling back a temporary
table. The MariaDB execution used the same shared SQL generated by the MySQL
8.4 dialect; its own registry paths were checked by the MariaDB unit tests.
Only pre-existing images were used, with no published ports or persistent
volumes, and the test containers were removed afterwards.

No external database or actual Aurora cluster was used. MySQL 9.x and the older
5.x boundaries were checked through SQL generation rather than live servers.
